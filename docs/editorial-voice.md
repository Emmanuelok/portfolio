# Kingxford editorial voice

Kingxford writes as a research, design, and software practice. The language should be precise enough for an institutional reader and clear enough for a first-time visitor.

## Principles

1. **Describe the work.** Name the task, evidence, method, decision, output, or limitation. Do not substitute “intelligence” for a specific capability.
2. **Use AI only as a factual term.** Say “AI-assisted review” when a model is called. Say “local review” when rules run in the browser or server without a model.
3. **Make claims inspectable.** Prefer “stores revisions in this browser” to “preserves the whole.” Prefer “sources remain linked” to “keeps the intelligence.”
4. **Keep product terms limited.** Canvas is the editor. Project Atlas is the project record. Project review coordinates phase-specific review. Human approval remains explicit.
5. **Use restrained calls to action.** A call to action should state what happens next: “Open the workspace,” “Review the case studies,” or “Prepare an email draft.”
6. **State boundaries where they matter.** Distinguish prototypes from live services, local storage from cloud persistence, and proposals from approved changes.

## Avoid

- Generic superlatives such as “revolutionary,” “world-class,” “unprecedented,” and “cutting-edge.”
- Repeated abstractions such as “intelligence system,” “specialist intelligence,” “abundant future,” and “transform complexity.”
- Claims of readiness that are not connected to runtime state.
- Anthropomorphic descriptions of models or review routines.
- Sentence fragments used only to sound dramatic.

## Preferred terminology

| Instead of | Use |
| --- | --- |
| Intelligence platform | Project platform or workspace |
| Conductor | Project review |
| Specialist agents | Review disciplines or specialist reviews |
| Project memory | Project record |
| AI-powered | AI-assisted, followed by the specific task |
| Smart | Automated, assisted, rule-based, or adaptive, as applicable |
| Human in the loop | Human approval required |

Technical identifiers and stored schema values may retain their existing names when changing them would break compatibility. User-facing labels should follow this guide.
